# M2 Audit Table

| Area audited | Finding in `ai-sample.html` | Evidence | Impact | Priority | Recommended revision |
|---|---|---|---|---|---|
| Page structure | The AI generated one long homepage instead of four separate pages. | Only one HTML document contains all sections. | The portfolio does not meet the required multi-page structure. | High | Create `index.html`, `about.html`, `skills.html`, and `contact.html`. |
| Semantic HTML | Several content areas use generic `<div>` elements. | Project cards and layout containers are built with `<div>`. | The document structure is less meaningful for browsers and screen readers. | High | Use semantic elements such as `<article>`, `<section>`, `<header>`, `<main>`, and `<footer>`. |
| Navigation | Links point to sections on the same page. | Links use `href="#about"`, `href="#projects"`, and `href="#contact"`. | Users cannot navigate between separate portfolio pages. | High | Link to the correct files, such as `about.html` and `contact.html`. |
| Skills presentation | Skills are displayed as an unordered list. | The skills section uses `<ul>` and `<li>`. | It does not provide the required structured data table. | High | Create a table in `skills.html` with `<caption>`, `<thead>`, `<tbody>`, and `<th scope>`. |
| Contact functionality | There is no contact form. | The contact area only displays email and phone text. | Visitors cannot submit a message through the page. | High | Add labelled name, email, subject, and message fields with suitable input types. |
| Form accessibility | No form labels or field relationships exist. | There are no `<label for>` elements because there is no form. | Screen-reader users may not understand form fields. | High | Give every form control a matching `id` and `<label for>`. |
| Images | The profile picture is represented by a styled `<div>`. | The code displays the letters “JR” instead of an image. | There is no meaningful visual image or image alternative text. | Medium | Use an actual image when available and add meaningful `alt` text. |
| Project structure | Projects use generic containers. | Each project is inside a `<div class="project-card">`. | Project content is less clearly identified semantically. | Medium | Replace project card containers with `<article>` elements. |
| External links | New-tab links lack security attributes. | Links use `target="_blank"` without `rel`. | This creates an avoidable security risk. | Medium | Add `rel="noopener noreferrer"` to external links. |
| Contact links | Email and phone details are plain text. | Email and phone are inside ordinary `<p>` elements. | Users must manually copy the information. | Medium | Use `mailto:` and `tel:` links. |
| Responsive design | The project grid always uses three columns. | CSS uses `grid-template-columns: repeat(3, 1fr)`. | The layout may be difficult to use on small screens. | Medium | Add media queries that reduce the number of columns on smaller screens. |
| CSS organization | All CSS is embedded in the homepage. | Styles are inside a `<style>` element in the document. | Reusing the same design across four pages is harder. | Low | Move shared styles into a separate CSS file. |
| Keyboard accessibility | No visible focus styling is provided. | There are no `:focus` styles in the CSS. | Keyboard users may lose track of the focused link or control. | Medium | Add clear focus styles for links, buttons, and form controls. |
| Original AI sample | The generated page must remain unchanged for comparison. | The file is saved as `ai-sample.html`. | Editing the sample would make the comparison unreliable. | High | Keep `ai-sample.html` unchanged and make revisions in the required portfolio files. |
| Verification | The AI output was not tested against all assignment requirements. | The generated page contains no evidence of testing. | Structural and accessibility problems may remain unnoticed. | High | Inspect the HTML, open every page in a browser, test links and form fields, and record the results. |
